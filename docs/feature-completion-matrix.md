# Feature completion and acceptance matrix

**Status: acceptance checklist, not a completion declaration.** This reflects the checked-out source/worktree and `docs/implementation-tracker.md` / `docs/status.md`. A source checkbox or passing fixture test proves neither deployed-image identity nor live provider/database behavior. Worktree-only changes are not attributable to deployed commit `adcfe7a`. Overall product status remains Alpha / not production qualified.

## Completion gates

A feature may be called **wired** only when its runtime owner invokes the implementation and the supported configuration path reaches it. Mark **accepted** only after all applicable checks below pass, evidence is recorded, and the tested image/configuration is identified. Fixture/unit coverage is useful evidence but cannot satisfy live qualification. “Needs live qualification” means code may be wired but operational acceptance remains open. Do not mark a feature complete merely because a helper, API route, test, migration, UI, or CI job exists.

## Evidence record required per accepted row

For each row promoted to accepted, record: source commit and deployed image digest; effective configuration and provider/database versions; exact commands or reproducible manual steps; results including failure cases; test/run identifiers and logs; operator and date; known limitations. Keep fixture results, CI configuration, successful CI execution, and live qualification as distinct evidence types.
